# devlanes-config

Parses and validates devlanes project and user YAML configuration, with source-labelled errors and JSON Schema generation. The daemon loads configuration through this crate; the resolver supplies runtime values for its MiniJinja expressions, and the composition root registers preset parsers and schemas.

## Usage

```rust
use devlanes_config::{ConfigError, parse_project, validate};

fn main() -> Result<(), ConfigError> {
    let project = parse_project(
        "project: demo\nservices:\n  api: { run: server }\n",
        Some("services:\n  api: { autostart: false }\n"),
    )?;
    let report = validate(&project)?;
    assert_eq!(report.project, "demo");
    Ok(())
}
```

Use `load_project(path)` for a file or directory. It also reads the sibling `devlanes.local.yaml`; loading is synchronous, so async callers should use a blocking worker.

## API

- `ProjectConfig` and `UserConfig`: separate typed project and machine settings.
- `check(path)`: load and validate a project, returning warnings or a `ConfigError`.
- `evaluate_typed`, `evaluate_env`, and `resolve_lane_vars`: resolve expressions using a caller-supplied `ExpressionContext`.
- `validate_with_presets`: pass opaque preset option objects to registered integration parsers.
- `project_schema_with_presets`: generate a project schema with integration-owned option schemas; `project_schema()` omits registration.
- `user_schema()`: generate the separate user configuration schema.
- `StartupConfig::windows(cores)`: effective start-gate windows for this machine. `DEFAULT_STARTUP_MODE` is the one place the default `startup.mode` is set.

## Merge and expression rules

Local overrides merge before `extends` resolution, and both follow one rule: mappings merge by key at every level (services, tasks, infra commands, containers, `ready`, `stop`, `env`, `vars`, `tags`, preset options), while lists and scalars replace. Alternative forms clear each other: setting `run`, `run_script` or task `steps` drops the others, setting one of `tcp`, `http`, `log` or `cmd` under `ready` drops the rest, and `ready: started` replaces a check mapping. So `stop: { timeout: 20s }` keeps an inherited `signal`. Task declaration order is preserved.

`${{ env.X }}` reads the supplied outer environment, including inside an env override map. Lane variables can reference other lane variables; cycles are rejected. Write `${{ '${{' }}` for a literal `${{`. Parsing does not read the process environment or run integration commands.

`validate_with_preset_ports` also counts each registered preset's named ports against a fixed `lanes.block_size`. `UserConfig::warnings()` lists settings that loading ignored, such as mobile trust targets.

## Schema

`schema.json` and `user-schema.json` sit beside this README and are generated by `cargo build -p devlanes`. Keep the generated files in Git; edit the Rust types rather than the JSON. The project schema includes the registered preset options.

Use this modeline in `devlanes.yaml` or `devlanes.local.yaml`:

```yaml
# yaml-language-server: $schema=https://devlanes.run/schema/v1.json
```

For user configuration, use `# yaml-language-server: $schema=https://devlanes.run/schema/user-v1.json`.
