# W11: remote client

A Windows machine connects to Linux and macOS boxes with `devlanes remote connect`. Each connection is one `ssh.exe` (the Windows OpenSSH Client, else the first `ssh.exe` on `PATH`) that checks the box and then runs `devlanes tunnel --stdio` there, so it authenticates once. Passphrase and host-key prompts come back through `devlanes.exe` itself as `SSH_ASKPASS`, over a named pipe only the daemon's own process may serve. Mirrored ports, HTTPS hostnames and synced folders work as on macOS and Linux; synced files keep only the read-only attribute, and box names Windows cannot hold are listed as errors instead of written. A Windows machine cannot be a box.

## Try it

From Git Bash with Docker Desktop running. Start the throwaway box from `e2e/ssh` with a lane the way `e2e/ssh/run.sh` does (a Linux `devlanes` mounted at `/usr/local/bin/devlanes`, a key without a passphrase in `AUTHORIZED_KEY`, `ssh-keyscan` into a `known_hosts` file, then `devlanes start` in `~/app` on the box). Set `MSYS_NO_PATHCONV=1` for the `docker` calls, or Git Bash rewrites `-v` and `-e` paths. The CLI cannot answer prompts on Windows yet, so use a key without a passphrase, or one in the `ssh-agent` service.

Then add a `Host devlanes-box` entry to `%USERPROFILE%\.ssh\config` with `HostName 127.0.0.1`, `User devlanes`, the container's `Port`, `IdentityFile` and `UserKnownHostsFile` (forward slashes, double quotes around paths with spaces), and remove it when done:

```sh
cargo build -p devlanes
export PATH="$PWD/target/debug:$PATH"
export DEVLANES_HOME="$(cygpath -w "$(mktemp -d)")"
devlanes remote connect devlanes-box --background
devlanes remote ls
```

`remote ls` shows the box connected, its echo port mirrored on `127.0.0.1` and `::1`, and the synced folder under `%DEVLANES_HOME%\sync` in state `watching`. `devlanes daemon stop --yes` ends the daemon and its `ssh.exe`.

The `needs ssh` tests run against the same box: set `DEVLANES_TEST_SSH_DEST=devlanes@127.0.0.1`, `DEVLANES_TEST_SSH_PORT`, `DEVLANES_TEST_SSH_KEY`, `DEVLANES_TEST_SSH_KNOWN_HOSTS` (Windows paths) and `DEVLANES_TEST_SSH_LANE=1`, and for the askpass test a passphrase key with `DEVLANES_TEST_SSH_PASSPHRASE` and `DEVLANES_TEST_SSH_ASKPASS_EXE` pointing at `target\debug\devlanes.exe`, then run `cargo test -p devlanes-transport-ssh --test it -- --ignored`.
