# W2: the daemon over named pipes

On Windows the CLI starts the daemon on its own and talks to it over a named pipe, `\\.\pipe\devlanes-<hash of the home>`, that only the same user can open. The daemon refuses to run elevated, keeps its home private to the user, SYSTEM and Administrators, and is detached from the terminal that started it. Services do not run on Windows yet; that is the next step.

## Try it

Run from the repository root in Git Bash, with an isolated home so nothing touches `~/.devlanes`:

```sh
cargo build -p devlanes
export PATH="$PWD/target/debug:$PATH"
export DEVLANES_HOME="$(cygpath -w "$(mktemp -d)")"
devlanes status
devlanes daemon status --json
devlanes doctor
devlanes daemon stop
```

`cygpath -w` turns Git Bash's `/tmp/...` into the Windows path under `%TEMP%` that the daemon, a native program, understands.

`status` finds no daemon, starts one and prints `no lanes`. `daemon status --json` shows its pid and pipe name, and `doctor` checks the daemon, the home, the proxy ports and the terminal. A terminal running as administrator fails the terminal check, since the daemon would refuse to start from it.

The daemon also starts from inside command substitution, which needs it to let go of the terminal's console and output:

```sh
out=$(devlanes status); echo "$out"
devlanes daemon stop
```

The first line returns right away instead of waiting for the daemon to exit.

The same commands work from cmd and PowerShell; only setting the home differs:

```bat
set DEVLANES_HOME=%TEMP%\devlanes-try
```

```powershell
$env:DEVLANES_HOME = "$env:TEMP\devlanes-try"
```
