# W5: graceful stops and the daemon's lifecycle

Stopping a unit asks it first. `SIGINT` sends Ctrl-C, other stop signals send Ctrl-Break, and visible windows get `WM_CLOSE`. Only what still runs at the stop timeout is terminated. An `npm.cmd` shim waiting at "Terminate batch job (Y/N)?" does not hold the stop. Tasks keep the daemons they start (processes that left the task's console) and end their leftovers. Processes devlanes runs for itself open no console windows. `devlanes daemon install` starts the daemon at logon without a window, and logoff stops units the way a signal does on macOS and Linux.

## Try it

Any Node project with a dev server works. With an isolated home in PowerShell:

```powershell
$env:DEVLANES_HOME = "$env:TEMP\devlanes-try"
cd C:\path\to\a\node\project   # with a devlanes.yaml running `npm run dev`
devlanes start
devlanes stop
devlanes logs <service> --tail 5
```

`stop` reports `interrupted (Ctrl-C)` within a fraction of a second, and a server that handles `SIGBREAK` logs it before exiting.

Starting at logon:

```powershell
devlanes daemon install
devlanes daemon status
devlanes daemon uninstall
devlanes daemon stop
```

`install` writes the `devlanes` value under `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` and starts the daemon; `daemon status` shows `logon: starts at logon`. `uninstall` removes the value and leaves the running daemon alone, so `daemon stop` ends it. `devlanesw.exe`, which the entry runs, is built with `cargo build -p devlanes-logon-launcher`.
