# W7: Docker and Compose

Lanes with `infra:` run on Windows against Docker Desktop. devlanes finds the engine the way the `docker` CLI does (`DOCKER_HOST`, then the current context in `%USERPROFILE%\.docker`, else `npipe:////./pipe/docker_engine`), and Compose runs as on macOS and Linux. Each lane gets its own containers for `per_lane` services next to the shared ones.

## Try it

With Docker Desktop running, from Git Bash with an isolated home, in a scratch copy of `fixtures/compose-pg-redis` that is its own Git repository:

```sh
cargo build -p devlanes -p devlanes-testing
export PATH="$PWD/target/debug:$PATH"
export DEVLANES_HOME="$(cygpath -w "$(mktemp -d)")"
cp -r fixtures/compose-pg-redis /tmp/pg-redis && cd /tmp/pg-redis
git init -q && git add . && git commit -qm init
git worktree add ../pg-redis-lane1 -b lane1
devlanes start
(cd ../pg-redis-lane1 && devlanes start)
devlanes status
docker ps --format '{{.Names}} {{.Ports}}'
```

`status` shows `fixture-pg-redis@0` and `@1` running, and `docker ps` lists one Postgres per lane on its own port plus the shared Redis. To clean up:

```sh
devlanes lane clean 1 --yes
devlanes lane clean 0 --yes
devlanes daemon stop
docker compose -p devlanes-fixture-pg-redis down -v
```

The Docker tests run by hand on Windows like elsewhere: `cargo nextest run --run-ignored only -E 'test(/^docker_/)'` for the crates, and `cargo nextest run --profile e2e --run-ignored only -E 'test(/docker_/)'` for the end-to-end ones.
