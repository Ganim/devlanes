# Config reference

<!-- Generated from crates/config/schema.json and crates/config/user-schema.json by crates/config/tests/it/reference_docs.rs. Edit the doc comments in crates/config, then run DEVLANES_BLESS=1 cargo nextest run -p devlanes-config. -->

Every field of `devlanes.yaml` and of the per-user `config.yaml`, generated from the JSON Schemas devlanes publishes. In a path, `<name>` stands for a key you choose (a service, task or profile name) and `[]` for an item of a list. A type marked *templated* also accepts a `${{ ... }}` expression, evaluated for each lane. A *duration* is a number with `ms`, `s`, `m`, `h` or `d`, and a *scalar* is a string, number or boolean. [examples/devlanes.yaml](../examples/devlanes.yaml) shows the fields in context.

## Project config

`devlanes.yaml` at the repository root (or a subdirectory, in a monorepo), with optional overrides in `devlanes.local.yaml` next to it. Schema: `https://devlanes.run/v1/schema.json`.

### global_env

| Path | Type | Description | Example |
| --- | --- | --- | --- |
| `global_env` | map of scalar (templated) | Variables for every service and task of the lane, above devlanes' own variables (`PORT`, `DEVLANES_*`) and below each unit's `env` and the profile's `env`. Use it for values many units share, such as a database URL built from `${{ infra.postgres.port }}`. Never set `PORT` here: it would replace every service's own port. | `{"API_URL":"${{ services.api.url }}"}` |

### lanes

| Path | Type | Description | Example |
| --- | --- | --- | --- |
| `lanes` | object | Which worktrees get a lane, where new worktrees are created, how many ports each lane reserves, and values computed per lane (`lane.<name>`). | `{"hosts_file":"always","primary":"main","vars":{"db_name":"acme_${{ lane.name }}"}}` |
| `lanes.block_size` | integer (templated) | Number of ports reserved for each lane. By default devlanes counts the ports the config needs and adds half again, rounded up to ten. A fixed size smaller than what the config needs is an error. | `80` |
| `lanes.hosts_file` | `auto` or `never` or `always` | Whether this project's hostnames are also written to `/etc/hosts`, for programs that cannot resolve `*.localhost` by themselves (Wrangler's workerd, musl or pure-Go binaries). Overrides the user's `hostnames.hosts_file` (default `auto`), except that a user `never` always wins. Writing needs the helper installed by `devlanes certs trust --hosts`, and only exact names are written, never wildcards. Values: `auto`: Write the exact hostnames only when the daemon's startup check finds that the system resolver does not answer `*.localhost` with a loopback address. `never`: Never write hostnames to `/etc/hosts`. Set in the user config, it applies to every project whatever the project sets. `always`: Always write the exact hostnames, even when the system resolver handles `*.localhost`, for programs that send `*.localhost` to DNS themselves. | `auto` |
| `lanes.matrix` | list of map of scalar (templated) | Fixed values per lane instead of computed `vars`: entry N holds lane N's values, read as `lane.<name>`. A lane whose index has no entry fails to resolve. Cannot be combined with `vars`. | `[{"domain":"acme.localhost","port":20000},{"domain":"acme-1.localhost","port":20100}]` |
| `lanes.max` | integer (templated) | Most lanes the project may hold at once; further worktrees stay unassigned, without ports. Lowering it keeps existing lanes. Unset, the number of lanes is limited only by free port blocks. | `6` |
| `lanes.new_worktrees` | `register` or `setup` or `start` | What devlanes does when a worktree gets its lane: only reserve it, also set it up, or also start it. Defaults to `register`. A worktree gets a lane the first time devlanes runs in it or `devlanes lane new` creates it, not merely because it exists. Values: `register`: Only reserve the lane (its index, port block and domain); nothing runs until the lane is started. `setup`: Also run infrastructure setup and `lane.create` tasks, leaving services stopped. `start`: Also start the lane with the default profile. | `register` |
| `lanes.primary` | string | Branch whose worktree is lane 0, the main lane (`lanes.main` in expressions) and the only worktree that gets a lane by itself. Defaults to the remote's default branch, else `main` or `master`. | `main` |
| `lanes.removed_worktrees` | `stop` or `clean` | What happens to a running lane whose worktree folder is deleted. Defaults to `stop`. A lane whose folder is gone and that runs nothing is cleaned; its logs stay until log retention removes them. Values: `stop`: Stop the lane's processes; once nothing runs, the lane is cleaned. `clean`: Clean the lane right away: stop its processes, run `lane.clean` tasks and `infra.teardown`, and free its index and ports. | `stop` |
| `lanes.vars` | map of scalar (templated) | Values computed for each lane and read as `${{ lane.<name> }}`, such as a database name, vhost, bucket or Redis index per lane. A var named `domain` replaces the default lane domain, and one named `port` fixes where the lane's port block starts. Cannot be combined with `matrix`. | `{"db_name":"acme_${{ lane.name }}"}` |
| `lanes.worktree_dir` | string (templated) | Directory where `devlanes lane new` creates worktrees, relative to the project directory of the primary worktree. Defaults to `../<project>-lanes`. Expressions can only use `project.*` here. | `../${{ project.name }}-lanes` |
